# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Vox is a Windows 11 screen reader built in C#/.NET 9 (`net9.0-windows10.0.19041.0`). It uses UI Automation (UIA) for accessibility, SAPI5 (`System.Speech`) and OneCore (`Windows.Media.SpeechSynthesis`, `WaveSpeechEngine`, played through the earcon output) for speech, NAudio for earcons, and a virtual buffer model for web browsing. Phase 1 (browse-mode reading of web pages in Edge/Chrome) is done; the commercial-parity milestones in `COMMERCIAL_PARITY_PLAN.md` follow (Milestone A — robustness, desktop text and controls, secure screens, audio and diagnostics —, Milestone B — web parity, settings, help and install — and Milestone C — braille — and Milestone D — workplace apps, profiles, languages and enterprise deployment — are done; Milestone E — text recognition, AI descriptions, the add-on API and store, remote access, and the release-quality security checklist (`docs/security.md`) and beta programme (`docs/beta.md`, `.github/ISSUE_TEMPLATE/`) — is done).

## Build, Run & Test

```bash
dotnet build                          # Build entire solution (Vox.sln)
dotnet run --project src/Vox.App      # Run the screen reader (no admin needed; see docs/signing.md for reading elevated windows)
dotnet test                           # Run all tests (xUnit + Moq)
dotnet build && dotnet test           # Validation gate — both must pass before committing

# Single test class / single test
dotnet test --filter "FullyQualifiedName~Vox.Core.Tests.Buffer.VBufferCursorTests"
dotnet test --filter "FullyQualifiedName~VBufferCursorTests.NextChar_AdvancesOffsetByOne"
```

All projects target `net9.0-windows10.0.19041.0` (the versioned Windows TFM gives the WinRT projection, used for OneCore speech) and `Vox.Core`/tests use WinForms, so running tests requires Windows; CI (`.github/workflows/ci.yml`, `windows-latest`) builds and tests every push. On Linux, `dotnet build -p:EnableWindowsTargeting=true` builds the solution. Tests needing live UIA COM are marked `[Fact(Skip = ...)]`.

Projects: `Vox.Core` (everything testable), `Vox.Sdk` (the public add-on API; references nothing of Vox; `docs/addons.md`), `Vox.App` (the screen reader; `--secure` for the sign-in/lock/UAC screens, `--safe` for no add-ons; tools: `--pack-addon <folder> <package> [key.pem]`, `--sign-catalogue <catalogue.json> <key.pem>`, `--remote-relay [port]`), `Vox.Watchdog` (restarts Vox.App after a crash), `Vox.Service` (Windows service that keeps a secure-mode Vox on the Winlogon desktop), `Vox.Core.Tests`, `samples/Vox.SampleAddOn` (an add-on using every part of the API; built in CI, which packages it; the tests load it from `SampleAddOn\` beside them), `Vox.Benchmarks` (BenchmarkDotNet: buffer build, cursor, text rules; `docs/benchmarks.md`), `Vox.E2E.Tests` (Vox in-process with a recording engine against Edge and the `tests/pages/` corpus, Notepad, Explorer and Settings, and fault injection through `tests/Vox.FaultTestApp`; keys through `SendInput`; skipped unless `VOX_E2E=1`, the soak test also needs `VOX_SOAK=1`; run as a program it is an interactive runner; see `docs/e2e.md`). Signed builds ask for UI access (`docs/signing.md`); `installer/Vox.Installer` (WiX v5, Windows only, not in the solution; built by the manual Release workflow, which also makes a portable zip and optionally a GitHub release) makes the MSI (`docs/installer.md`; the user-facing install guide is `docs/install.md`); the optional eSpeak NG engine (`docs/espeak.md`) and MathCAT math speech (`docs/mathcat.md`, `IMathSpeech`; `NoMathSpeech` when absent) are installed separately.

The `Vox.App` build copies `assets/config/default-settings.json`, `default-keymap.json`, `laptop-keymap.json` and the earcon schemes (`assets/sounds/<scheme>/manifest.json` + WAVs; `EarconScheme` setting, other schemes fall back to `default`) into `bin/.../assets/` (MSBuild target in `Vox.App.csproj`; `PublishVoxAssets` copies them and the guide into the publish folder too); they are resolved relative to `AppContext.BaseDirectory` at runtime. The keymaps are also embedded in Vox.Core as a fallback (`KeyMap.LoadBuiltIn`). The `KeyboardLayout` setting picks Desktop (`default-keymap.json`) or Laptop (the desktop bindings without keypad keys, overlaid by `laptop-keymap.json`; `KeyMap.LoadLayout`); a change is applied live with `KeyInputDispatcher.SetKeyMap`. The user's `%APPDATA%/Vox/keymap.json` is layered on top (`KeyMap.LoadLayout(..., userKeyMapPath, ...)`; `"command": "None"` unbinds; duplicate keys and commands left without a key are logged as conflicts; not in secure mode; `docs/keymap.md`). User settings live in `%APPDATA%/Vox/settings.json`; Serilog logs go to `%LOCALAPPDATA%/Vox/logs/`. Those paths come from `VoxPaths` (`UserData`, `Components`): a portable copy (a `userConfig` folder beside the exe, made by `PortableCopy` from the Vox menu) keeps everything in that folder instead.

## Architecture

Startup: `Program.cs` → generic host → `ServiceRegistration.RegisterServices` (all components are DI singletons) → `ScreenReaderService` (the main `IHostedService`; `BrailleService` starts after it), which initializes UIA, applies settings (and re-applies changed values on change), installs the keyboard hook, runs the first-run wizard if `FirstRunCompleted` is false (before subscribing to UIA events, so focus speech can't interrupt it), subscribes to UIA events, and wires pipeline events to `BrowseModeController` and `BrowseDocumentTracker`. The wizard ends by offering practice lessons (`TutorialLessons`: web pages, editing text, reviewing the screen; each step names a command whose key comes from the keymap in use), also run alone from the Vox menu (RunTutorial). It also handles the app-level commands the controller raises: Quit (Insert+Q pressed twice → `IHostApplicationLifetime.StopApplication`) and RunSetup (Insert+Ctrl+S → re-runs the wizard with `KeyInputDispatcher` stopped and `SpeechQueue` suspended). `ScreenReaderService` only connects components; navigation logic lives in `BrowseModeController` (Vox.Core, unit-tested).

Event flow:

```
KeyboardHook (WH_KEYBOARD_LL) ─> bounded channel ─> KeyInputDispatcher ─┐  (KeyMap lookup → NavigationCommandEvent or RawKeyEvent)
UIAEventSubscriber (UIA callbacks) ──────────────────────────────────────┤
BrowseDocumentTracker (UIA thread: DocumentChanged / SubtreeChanged) ────┤
                                                                         v
                                       EventPipeline: Channel<ScreenReaderEvent>, single reader
                                       - coalesces FocusChangedEvents within 30ms (keeps last)
                                       - speaks focus / live-region / mode / typing-echo events directly
                                       - re-raises C# events (NavigationCommandReceived, RawKeyReceived,
                                         FocusChangedProcessed, DocumentChangedProcessed, ...)
                                                                         │
            ScreenReaderService handlers ─> BrowseModeController ─> NavigationManager (Browse/Focus mode)
                                                                 ─> QuickNavHandler + shared VBufferCursor
                                                                 ─> SayAllController, TypingEchoHandler,
                                                                    AnnouncementBuilder, Elements List
                                                                         v
                                       SpeechQueue: Channel<Utterance> ─> ISpeechEngine (SpeechEngineRegistry ─> OneCore / eSpeak / SAPI)
```

- **Event types** are records deriving from `ScreenReaderEvent` in `Pipeline/ScreenReaderEvent.cs`. Producers post via `IEventSink.Post` (non-blocking `TryWrite`). To add a new event, add the record and a `case` in `EventPipeline.ProcessEventAsync`. `PipelineWorkEvent(Timestamp, Action)` runs a piece of work on the pipeline thread (for results that come back on another thread, such as the update check).
- **SpeechQueue priorities**: `Interrupt > High > Normal > Low`. Enqueuing an `Interrupt` (or calling `CancelAll`) starts a new epoch: the utterance being spoken is cancelled immediately and anything queued earlier is dropped. Normal utterances within 50ms are concatenated. `EnqueueAndWaitAsync` completes when an utterance has been spoken (Say All uses it). Just before the engine call each utterance's text goes through `TextProcessor` (an ordered chain of `ITextRule`s registered in `ServiceRegistration`; a throwing rule is skipped); history and the utterance events keep the original text. Rules may also change the utterance (`ITextRule.ApplyTo`: `PitchOffset`, a `SoundCue` the queue plays first). Rules: `StateSoundsRule` (first: with the `StatesAsSounds` setting, `AnnouncementBuilder` marks checked/expanded/selected states and the rule turns the first into its earcon), `LanguageRule` (an utterance tagged with another language — page text read in browse mode and Say All, from UIA Culture captured into `VBufferNode.Language` — gets `Utterance.Voice` for that language; the `LanguageVoices` setting overrides), `CapitalsRule` (capital indication, separate settings for a character and for a word/line), `PronunciationRule` (user `%APPDATA%/Vox/dictionaries/user.json`, then `voices/<voice>.json`, then the built-in `assets/speech/dictionary-default.json`; reloaded on change; none in secure mode), then `PunctuationRule` (`symbols-en.json` + CLDR `emoji-en.json`, generated by `tools/cldr/generate_symbols.py`; embedded in Vox.Core; counts runs of 4+ of a symbol), then `NumbersRule` (digits setting). User navigation and focus changes use `Interrupt`; polite live regions use `Low`.
- **Speech engines**: `SpeechEngineRegistry` is the `ISpeechEngine` everything speaks through; it forwards to the engine named by the `SpeechEngine` setting (null: OneCore, then SAPI), switches at runtime, re-applies rate/pitch/volume/voice to a new engine, and falls back to the next engine when one fails to start or fails while speaking. `WaveSpeechEngine` (over an `IWaveSynthesizer`: OneCore's `WinRtOneCoreSynthesizer`, or eSpeak NG's `EspeakSynthesizer` when the optional component is installed — `docs/espeak.md`) plays its audio through `AudioCuePlayer` (`IAudioStreamPlayer`), so it uses the earcon output device.
- **Key handling**: `KeyboardHook` tracks modifiers itself (the LL hook reports left/right VK codes; missed key-ups are reconciled with `GetAsyncKeyState` and reset on session switch) and asks `IKeyboardHook.SuppressionFilter` (set by `KeyInputDispatcher`) for a `KeyDecision` on each key-down; bound keys are swallowed unless the keymap entry has `"passThrough": true`. The decision (including the mode it was resolved in) travels on `KeyEvent.Decision`, so the dispatcher acts on the key exactly as decided at press time. Key-ups of command keys are not posted as `RawKeyEvent`s. `KeyModifiers.Insert` means the screen reader modifier (Insert or CapsLock per settings); every key pressed with it is swallowed, and the modifier itself is swallowed unless tapped twice quickly on its own (`ModifierTapDetector`), which passes the key's own function through. Keypad keys with Num Lock off arrive as navigation keys; `KeyEvent.IsKeypad` marks them and `NumpadKeys.BindingCodes` resolves them as Numpad0–9 / Numpad Enter (269) first, then as the key they stand for (Num Lock digits are never bound). Browse- and Focus-mode bindings only apply while a web document has focus; outside documents only "Any" bindings apply (`KeyMap.TryResolveOutsideDocument`). A focus event for an element not in the buffer turns them off at once (so typing after Ctrl+L or Alt+Tab isn't swallowed); the tracker's `FocusInDocumentEvent` turns them back on when that element is in the current document after all. In Browse mode, unbound typing keys are swallowed so they can't trigger page shortcuts. Focus mode is entered automatically when focus *moves* to an edit-like control inside the document (a rich text editor too: a `contenteditable` group or document whose Value is writable, `FormControls.IsRichEditable`; its caret is then read through its TextPattern like any text control) (not for repeated focus events on the same element, nor for load-time focus on a page not visited before; returning to a remembered page with focus in a field does resume Focus mode), left automatically when focus moves to a control that doesn't need it (link, button, check box, radio button; menus and tab lists do need it), and left with Escape (passed to the page while a popup is open — an expanded combo box or menu item, or an item inside a popup menu, not a menu bar item — as decided at press time). Sleep mode (`SleepMode`, `SleepApps` setting, Insert+Shift+S; laptop Insert+Shift+Z): while a listed app has focus the speech queue's `IsMuted` gate drops everything and the dispatcher passes every key except the toggle (decided at press time from a cached flag, like Escape). A newly loaded document starts in Focus mode when `DocumentModes` says it is a web application (an element near the root with role application or an "editor" role description holding at least half its text) or the `AppDefaultModes` setting maps its process (`DocumentChangedEvent.ProcessName`) to Focus; Electron and WebView2 apps report the Chrome framework, so they are found like Chrome pages. Add-on commands' keys (`SetAddOnKeys`) are looked up before the keymap's, and while `KeyForwarder` is set (controlling a computer remotely) every key but the one bound to `ToggleRemoteControl` is swallowed and forwarded instead. Input help (Insert+1, `KeyInputDispatcher.IsInputHelpOn`, flipped by the dispatcher itself when it resolves the toggle) swallows every key but a lone modifier and posts an `InputHelpEvent` instead of the command; the pipeline says the key and the command's `CommandCatalog` name and description (`InputHelp`). Automatic mode switches play only the mode cue (`ModeChangedEvent.Announce = false`); user toggles are also spoken, queued at High priority.
- **UIA threading**: `UIAThread` owns a dedicated STA thread; every COM/UIA call must go through `UIAThread.RunAsync(...)` (bridged with `TaskCompletionSource`). Every call has a timeout (`DefaultTimeout` 2 s, `SetupTimeout`, `DocumentTimeout` for whole-document capture); a timed-out call throws `UIATimeoutException`, and `NotRespondingReporter` says "<app> not responding". `UIAWatchdog` replaces a thread stuck past its call's timeout and `UIARecovery` re-creates the automation object, subscriptions and document on the new one. No command handler may await the UIA thread (StopSpeech and Quit must work while it is stuck). UIA event handler callbacks in `UIAEventSubscriber` only post to the pipeline and return.
- **Desktop text**: `Vox.Core/Text` models text like UIA's TextPattern (`ITextDocument`/`ITextRange`, implemented by `UIATextDocument`, `StringTextDocument` for value-only edits, and `BufferTextDocument`). `UIAEventSubscriber.FollowFocusForTextAsync` subscribes caret/text/property/selection events on the focused element; `FocusedTextMonitor` + `TextCaretTracker` read caret moves, selection changes, deletions and spelling errors; `TerminalMonitor` reads new terminal output. Window titles and menu context are said before the focus announcement through `EventPipeline.FocusContextProvider` (said separately they would be interrupted).
- **User guide**: `docs/guide/` (index.html, guide.css) is copied beside Vox.App at build, and `keyboard.html` is generated there from the keymaps and `CommandCatalog` by `Vox.App --keyboard-reference <path>` (`KeyboardReference`; Windows builds); the Vox menu opens it.
- **Updates** (`Updates/`): `UpdateChecker` reads a feed only when its detached RSA signature verifies against `assets/config/update-key.pem` (no key file: no checks; never in secure mode), picks the newest release for the `UpdateChannel` setting, and installs on request only an MSI whose SHA-256 is the signed feed's; `UpdateCommands` runs the Vox menu's check (asking before installing) and the quiet daily check (`docs/updates.md`).
- **Run policy**: `RunPolicy` (`--secure`) says what an instance may do; secure mode never writes settings or touches the user profile, network, add-ons or AI. `SafeMode` (`--safe`) loads no add-on (they can still be managed); `RestartRequest` restarts into or out of it (under Vox.Watchdog, which passes `--supervised`, through exit codes `RestartSafe`/`RestartNormal`, never counted as crashes; alone, by starting the next instance with `--restarted`). Never log typed text or field values (`SensitiveTextLoggingTests`).
- **Object navigation and review**: `ObjectNavigator` (pure, over `INavigatorObject`, with simple-review skipping of unnamed groups/panes) and `ReviewCursor` (over any `ITextDocument`) live on the UIA thread inside `ObjectNavigationCommands` / `ReviewCommands`, which speak from within the UIA work item so quick presses are said in order. Review modes: navigator object, focused text, screen (window); while browsing, review is tethered to a `ReviewTether` snapshot of the buffer taken on the pipeline thread. `MouseTracker` polls the pointer (one `ElementFromPoint` lookup per 100 ms at most, none in flight twice) and speaks the object or line/word under it when it changes (`MouseTracking`, `MouseTextUnit`; Insert+M toggles). `MouseCommands` routes the pointer to the navigator object and clicks or locks the left button through `IMouseInput` (released on shutdown). Activating a browse-mode element (`BrowseDocumentTracker.ActivateAsync`) goes through `ElementActivation`: its pattern (Invoke, Toggle, SelectionItem, ExpandCollapse, a default action), else a left click at its clickable point (scrolled into view, the pointer put back), else focus.
- **Text recognition** (`Ocr/`, Milestone E; `docs/ocr.md`): `OcrCommands` (Insert+R the navigator object — while browsing, `BrowseModeController.RecognitionTarget`: the graphic at the browse cursor, else the page —, Insert+Ctrl+R the foreground window, Insert+Ctrl+Enter clicks the recognised word at the review cursor) gets a rectangle from `IOcrTargetSource` (`UIAOcrTargetSource`: `INavigatorObject.GetBounds`, `BrowseDocumentTracker.ElementBoundsAsync`, the window rectangle), a `CapturedImage` from `IScreenCapture` (`GdiScreenCapture`; unavailable in secure mode) and lines of `OcrWord`s with screen rectangles from `IOcrEngine` (`WindowsOcrEngine` over `Windows.Media.Ocr`, local; small captures enlarged by `OcrScaling`; language from `OcrLanguage`, else `Language`). The result is an `OcrDocument` (`ITextDocument` keeping word rectangles) the review cursor is put in (`ReviewCommands.ShowRecognizedAsync`) until focus, the caret, the review mode or the browse cursor moves. Untagged and scanned PDFs offer Insert+R on load (`PdfDocuments.LoadAnnouncement`, key from `BrowseModeController.KeyNameFor`). Recognised text is never logged.
- **AI** (`Ai/`, Milestone E; `docs/ai.md`): `AiAssistant` is the only way to an `IImageDescriber` — `LocalImageDescriber` (a vision model served by Ollama, `AiLocalModel`/`AiLocalEndpoint`, loopback addresses only) first, else `CloudImageDescriber` (Claude Messages API, raw HTTP over the `NetworkGate` client, `AiCloudProvider`/`AiModel`/`AiEndpoint`, key in `ProtectedAiKeyStore`, DPAPI, never in settings or logs) — after `AiConsent` (secure screens and `DisableAI` refuse everything; the cloud never gets a password field, an `AiPrivateApps` window or anything with the network off; `AiCloudConsent` ask once per session / allow / never, asked through `IAiConsentPrompt`); answers cached by `DescriptionCache`. `AiCommands`: Insert+G describes the navigator object (while browsing `RecognitionTarget`), Insert+Alt+G asks about the window (screenshot plus `IAiContextSource` window text), Insert+Ctrl+I summarises the page (AI, else `PageDigest`); answers go under the review cursor (`ReviewCommands.ShowRecognizedAsync` takes any `ITextDocument`); progress cue while waiting, the key again or Ctrl cancels. Insert+Ctrl+M (`MainContent`) moves to the main content; `CaptchaDetector` announces CAPTCHAs with their accessible way through (never solves them). AI settings are `ProfileManager.GlobalSettings`. Prompts are `TextPromptDialog`s run through `OwnDialogRunner` (browse keys off while open).
- **Add-ons** (`AddOns/`, Milestone E; `docs/addons.md`): add-ons reference only `Vox.Sdk` (`IAddOn.Initialize(IAddOnHost)`; `AddOnCommand` with `KeyGesture`s, `IAppModule`, `IGlobalPlugin`, `IAnnouncementFilter`, `ISpeechEngine`, `IBrailleDriver`, `VoxEvent`s — never keys, typed text or a password's value; `VoxApi.Current` is the API version). A package (`.voxaddon`, `AddOnPackage`) is a zip with `addon.json` (`AddOnManifest`: id, version, min/max API, author, entry assembly, every file's SHA-256) and optionally `addon.sig`/`addon.pem` (RSA over the manifest); `AddOnTrustStore` (`assets/config/addon-key.pem` + `%APPDATA%/Vox/addons/trusted-keys`) says whether its publisher is trusted; `AddOnCompatibility` refuses another major API with a spoken reason. `AddOnManager` (pipeline thread for loading and calls) installs into `%APPDATA%/Vox/addons/<id>` (`state.json`: disabled / turned off), loads each in its own collectible `AssemblyLoadContext` (`AssemblyAddOnLoader`: assemblies read into memory after a hash check, `Vox.Sdk` shared), and hands what it added to Vox through `AddOnIntegration`: app modules to `AppModuleManager.SetAddOnModules` (before Vox's own; a disabled one falls through to the next), commands' keys to `KeyInputDispatcher.SetAddOnKeys` (`AddOnKeyLayer`, before Vox's keys; the active add-on module's while active — `AppModuleManager.ActiveModuleChanged` → `RefreshKeys`; pressed → `AddOnCommandEvent` → `AddOnCommands.Run`; input help describes them), filters to `AddOnTextRule` (after `PronunciationRule`), plug-ins to the pipeline's filter/formatter/`EventProcessed` (after the app module), engines to `SpeechEngineRegistry.Add`, drivers to `BrailleDisplayManager.AddDriver`; disable/remove/update/turn-off takes it all back out and unloads. Every call goes through its `AddOnGuard` (5 failures a minute: turned off and said). `AddOnStore` reads the signed catalogue (`AddOnCatalogue`; https or a local `file:`; `AddOnCatalogueUrl`) through NetworkGate's client and installs only a package with the catalogue's SHA-256. `AddOnCommands` runs the Vox menu's Manage add-ons / Add-on store dialogs (`AddOnsDialog`, `AddOnStoreDialog` over `IAddOnActions`) and Restart with add-ons disabled.
- **Remote access** (`Remote/`, Milestone E; `docs/remote.md`): `RemoteAccessSession` connects two Vox computers: the controlled one waits (`RemoteTransport.ListenAsync`, or at a relay) with a `RemoteCode` (12 base32 characters), the controlling one connects; `SecureChannel` (ECDH P-256 + PBKDF2 of the code + HKDF, AES-GCM frames with per-direction keys and counters) carries JSON `RemoteMessage`s. Controlling side: `ToggleRemoteControl` (Insert+F11) sets `KeyInputDispatcher.KeyForwarder`, which swallows every key but the toggle and sends it (down and up, the screen reader key marked) — the controlled side plays them with `RemoteKeyPlayer` through `SendInput` (its own screen reader key; all released when control stops). Controlled side: `SpeechQueue.UtteranceQueued` and `BrailleController.LineShown` go back and are spoken / shown there. Both sides say when it starts and ends; `DisconnectRemote` (Insert+Ctrl+F11). `RemoteRelayServer` (`Vox.App --remote-relay`) pairs the two by a PBKDF2 hash of the code and pipes the encrypted bytes. Never on secure screens or with the network off; sockets only after `NetworkGate.MayConnect`. `RemoteCommands` runs the Vox menu's Remote access dialog (`RemoteDialog`).
- **Virtual buffer** (`Buffer/`): `VBufferBuilder` walks an `IVBufferElement` tree (abstraction over UIA elements, mockable in tests) into a `VBufferDocument` with a flat text string plus prebuilt indices (Headings, Links, FormFields, Landmarks, FocusableElements, Tables, Buttons/Edits/ComboBoxes/CheckBoxes/RadioButtons for B/E/C/X/R, and Lists/ListItems/Graphics/BlockQuotes/Frames/Separators/EmbeddedObjects for L/I/G/Q/M/S/O, classified by `PageElements`), and a `TableModel` per table (cells placed with row/column spans from UIA GridItem, column/row header cells, layout-table heuristic; `FindTableCell`). `QuickNavHandler` also filters links by visited state (V/U), skips headings the cursor has been on in this page (J), finds text lines after a block of links or of plain prose (N/P, over the buffer's `\n`-separated lines) and the end/start of the enclosing list, table, landmark, block quote or frame (`,`/Shift+`,`). Moving the browse cursor (except by character) says list boundaries crossed before the text (`ListAnnouncer`: "out of list" per list left, "list with N items" plus "nesting level N" per list entered; not at Advanced verbosity); annotations — comments, insertions, deletions, highlights, from the ARIA role or UIA AnnotationTypes, `Annotations` — are said on entry and exit on every move, character moves included; so are figures ("figure" / "out of figure"), outermost plain elements Chromium offers Invoke on (a click handler: "clickable", `VBufferNode.IsClickable`) and, with `ExpandAbbreviations`, an `abbr`'s expansion). While a modal `dialog`/`alertdialog` (`aria-modal`) is open, `VBufferDocument.ModalScope` is its text span: quick nav, cursor moves (a boundary cue at its edges; top/bottom go to its edges), Say All and the cursor after a load or update stay inside it. A node emits its Name only if no descendant emitted text (avoids Chromium's duplicate link/heading text). ARIA states are read as Core-AAM maps them to UIA (`AriaStates`): invalid (IsDataValidForForm, with the error message resolved from ControllerFor runtime ids by `VBufferDocument.ErrorMessageOf`, also for focus events through `EventPipeline.ErrorMessageProvider`), current/sort/pressed (AriaProperties; toggle buttons say "pressed"), role description (LocalizedControlType), key shortcuts (AcceleratorKey) and details (DescribedBy, "has details"). Form fields read as label plus value (never a password's value; capped at 1,000 characters in the buffer, and only the first line, up to 100 characters, is spoken on focus). `VBufferCursor` moves by line/word/char/paragraph over that, splitting lines longer than `MaxLineLength` (default 100) at a word boundary; `IncrementalUpdater` returns a new document (never mutates the old snapshot). With the `ScreenLayout` setting (default on) inline runs (links, inline text) are joined onto one line; off, every element has its own line (`VBufferDocument.ScreenLayout`, kept by updates; a change re-captures the page).
- **Live pages**: on each focus change `BrowseDocumentTracker` (UIA thread) finds the outermost web `Document` ancestor (`WebContent`: Chrome or Gecko framework, or anything but a Win32 window inside a Firefox `Mozilla*` window, for Firefox through the MSAA proxy; what still needs IAccessible2 is in `docs/firefox.md`), captures it with one cached `BuildUpdatedCache` call into a COM-free `UIAElementSnapshot` tree, builds the buffer and posts `DocumentChangedEvent`. StructureChanged events are scoped to that document, debounced, and re-captured as `SubtreeChangedEvent`s (tagged with the document id and the element's ancestor ids, so stale updates are dropped and unknown elements are spliced at their nearest known ancestor). A failed capture is not recorded as loaded and is retried once. Loading is staged: the part of the page a few levels above the focus (or its first top-level parts, ~200 elements) is posted first as a partial document (`DocumentChangedEvent.IsPartial`), then the whole page, which the controller takes like an update (cursor and mode kept; load announcements wait for it). `BufferBuildBudgetTests` holds the builder to 500 ms for 10,000 nodes. `BrowseModeController` keeps the cursor on the same character across updates and remembers the reading position of recently visited documents. `BrowseSelection` is the browse-mode selection (Shift/Ctrl+Shift+arrows, Shift/Ctrl+Shift+Home/End, Ctrl+A; from an anchor to the active end the cursor follows): any other cursor move or a new document ends it, an update outside it keeps it, and Ctrl+C copies it through `IClipboard`; it also keeps the Insert+F9 mark (per document, shifted by updates) that Insert+F10 selects from to the cursor, both included (pressed twice, copies). Vox's own modal dialogs (Elements List, the find prompt — both `VoxDialog`s on their own STA thread) turn browse keys off while open and report back with a pipeline event (`ElementsListClosedEvent`, `FindPromptClosedEvent`); `PageSummary` says the title, language and element counts (Insert+Shift+I) and the address of the link at the cursor (its UIA value; Insert+K). A PDF in Edge/Chrome is browsed as its tag tree like any page; `PdfDocuments` (the document's value is its address) says on load whether it is untagged (no headings, lists or data tables) or has no text. Math (`MathSpeech/`): `MathMarkup` rebuilds an expression's MathML from the buffer (role math, children with MathML tags as roles), moving onto it by line says it through MathCAT, and Insert+Alt+M explores it (`MathExplorer`: arrows become MathCAT navigation commands until another command). `OverlayDetector` finds an open modal dialog or a cookie/consent banner (the smallest container around a button whose text mentions cookies or consent) and its Reject/Close button (never one that also accepts); it is announced once per overlay at Normal priority after a load or update, and only Insert+Shift+D presses the button. `FindInBuffer` searches the flat text (case-insensitive by default, wrapping with the wrap cue, session-only history). Cross-thread results always come back as pipeline events so buffer/cursor state is only touched on the pipeline thread.
- **Braille** (`Braille/`, Milestone C; `docs/braille.md`): cells are bytes with bit n-1 for dot n (`BrailleDots`, also Unicode U+2800 conversion); `IBrailleDisplay` (`Write(cells, cursorPosition)` — the cells already show the cursor — and `KeyPressed` with the driver's key names and routing cell; `NoBrailleDisplay` when none) and `IBrailleTranslator` (`Translate` returns a `BrailleTranslation` with cells and the char↔cell maps for cursor and routing, optionally the word at the cursor uncontracted; `BackTranslate`): `LibLouisTranslator` (optional liblouis component in `VoxPaths.Components/liblouis`, loaded dynamically), else `ComputerBrailleTranslator` (NABCC; `BrailleTranslatorFactory`). Drivers implement `IBrailleDisplayDriver` (`TryConnect`, `Disconnect`, `Disconnected`): `HidBrailleDisplay` (`Braille/Hid/`, HID braille page 0x41) and `BrlttyDisplay` (`Braille/Brltty/`, BrlAPI over TCP, `docs/brltty.md`); `BrailleDisplayManager` auto-detects (HID, then BRLTTY; `BrailleDisplay` setting, "None" off), rescans every 3 s while none is connected. `BrailleController` (thread-safe, one lock, injectable `TimeProvider`) keeps the focus line, the caret/browse line and the review line, shows the one the tether (`BrailleTether`, Insert+Ctrl+T) picks, flashes what Vox says (`SpeechQueue.UtteranceQueued`) unless a line update came within 150 ms, blinks the cursor, and runs display keys through `BrailleKeyMap` (`assets/braille/keymaps/common.json` + the driver's file; dot chords are typed through `BrailleInput`, contracted words on Space/Enter; keys sent with `IKeyboardOutput`). `BraillePresenter` builds `BrailleLine`s (text, cursor, selection, source offsets; browse lines add role labels after links/buttons/fields/headings/graphics, from `BrailleLabels`/`assets/braille/labels-en.json`); `BrailleViewport` pans (word wrap) and draws cursor and selection (dots 7–8). `BrailleFeed` feeds it from focus events (ancestors via `UIAFocusAncestry`), `FocusedTextMonitor.DocumentRead` and `ReviewCommands.PositionShown` (UIA thread) and `BrowseModeController.BrowsePosition()` after pipeline events; routing goes through `IBrailleRouter` (`BrailleRouter`: caret via `ITextRange.Select`, browse cursor via `BrailleRouteEvent` → `BrowseModeController.RouteTo`). `Vox.App/BrailleService` (a second hosted service, after `ScreenReaderService`; not in secure mode) wires it up. Tests use `FakeBrailleDisplay` and `FakeBrailleTranslator` (one cell per character plus whole-word contractions).
- **App modules** (`AppModules/`, Milestone D; `docs/apps/`): an `IAppModule` (base `AppModule`) is support for one application, picked by `AppModuleManager` from the foreground process name (refreshed on every focus change, before the announcement, and on `ForegroundWindowChangedEvent`; `DisabledAppModules` turns modules off). While active its keys (`assets/apps/<id>.json`, embedded, keymap format; `KeyInputDispatcher.SetAppKeyMap` checks them before the keymap) and commands (`TryHandle`, before every other handler) apply, `FormatFocusAnnouncement` can replace or silence focus speech (`EventPipeline.FocusAnnouncementFormatter`), `ShouldProcess` drops events (`EventPipeline.EventFilter`) and `OnEvent` sees every handled event (`EventPipeline.EventProcessed`). Module members run on the pipeline thread; slow reads run off it and come back as `PipelineWorkEvent`s with a sequence number so late results are dropped. Office is read through its object model: `IOfficeObjectModel` (`OfficeObjectModel`: late-bound `dynamic` on its own STA thread, the application found from the document window's `OBJID_NATIVEOM`, else the running object table; null on any failure; tests use `FakeOfficeObjectModel` over plain C# fakes). Modules: Word (quick navigation with Insert+Alt+letter, comments and tracked changes at the caret, location, table cells), Excel (cells from the object model with titles from `ExcelTitleStore`, formula/comment/chart commands), Outlook (message rows in the chosen column order, headers, meetings, calendar), PowerPoint (slides, shapes, notes), Explorer (details-view rows through `IDetailsRowSource`), Teams and Zoom (`MeetingAppModule`: call state from the window's button names, `IWindowButtonSource`), and `QuietAppModule`s for VS Code, Visual Studio and Acrobat, which drop the application's announcements that repeat what Vox just said (`RecentSpeech`). New commands go at the end of `NavigationCommand` with a `CommandCatalog` entry in `CommandCategory.Applications`; their keys appear in the keyboard reference.
- **Configuration profiles** (`docs/profiles.md`): `ProfileManager` keeps sparse profiles (`ProfileStore`, `%APPDATA%/Vox/profiles/*.json`; none in secure mode) layered normal < application < Say All trigger < manual (`ProfileSettings.Merge`). `SettingsMonitor.CurrentValue` is the merged result (`NormalValue` the file's); `UpdateSettings` while a profile is active records the difference in the top profile (`ProfileManager.GlobalSettings` stay in the normal configuration). The foreground application comes from `AppModuleManager.ForegroundAppChanged`, Say All from `SayAllController.ReadingChanged`; the dialog is `ProfilesDialog` (Insert+Ctrl+P).
- **Localization** (`Localization/`, `docs/translating.md`): every spoken and UI string is in `Strings.resx` (translations `Strings.<lang>.resx`: es, fr, de, pt, zh, ja, ar, hi so far) and read through `VoxStrings` (`Get`/`Format`, at use time, in `VoxStrings.Culture` = the `Language` setting, else Windows'; `Use` puts a localizer in place for one async flow, for tests; DI's `IStringLocalizer<T>` reads the same). `StringResourceTests` checks every name the code asks for exists; the pseudo-locale test proves `AnnouncementBuilder` has no hard-coded English. Symbol names come from `SymbolDictionary.ForLanguage` (English levels, `symbols-<lang>.json` names) in the utterance's language, else Vox's. Text stays in logical order everywhere (Arabic and Hebrew braille read left to right); `BidiText` leaves invisible direction marks out of the buffer and braille, keeping cursor and routing maps; `VoxDialog`s lay out right to left in RTL languages.
- **Enterprise** (`Enterprise/`, `docs/enterprise.md`): settings are layered built-in defaults < machine defaults (`MachineSettings`: `%ProgramData%\Vox\machine-settings.json`, then `HKLM\Software\Vox\Defaults` from the MSI's properties) < the user's file and profiles < Group Policy (`PolicySettings` from `Software\Policies\Vox`, ADMX in `installer/policy`; enforced and locked settings, `SettingsMonitor` applies it last and the settings dialog shows locked fields as set by the organization; `DisableNetwork`/`DisableAddOns`/`DisableAI` restrict `RunPolicy`). Every network connection goes through `NetworkGate`. `RemoteSessionMonitor` detects RDP/Citrix (`docs/remote-sessions.md`).
- **Switching** (`Switching/`, Milestone F; spec `specs/switching.md`): importers of other screen readers' settings return the changed `VoxSettings` with an `ImportReport` (`ImportedItem`s with source, target, value and the value replaced; `SkippedItem`s with an `ImportSkipReason`), saving nothing themselves. `NvdaSettingsImporter` reads `nvda.ini` through `ConfigObjFile` (configobj INI, malformed lines kept by number) — synthesizer and voice (`VoiceMatcher`: NVDA's registry tokens to installed voice names), rate (`RateToWpm`, approximate), pitch, volume, symbol level, capitals, typing echo, keyboard layout and key, browse-mode line length/layout, braille — only what the file sets. `ImportFolder` adds `gestures.ini` (`NvdaGesturesImporter`: script names to `NavigationCommand`s, `KeymapImport` binds them in the modes the layout binds the command in) and the speech dictionaries (`NvdaDictionaryImporter`, Python regexes converted or skipped; `DictionaryImport` merges into `dictionaries/user.json` / `voices/<voice>.json`) as `PlannedFile`s, which `ImportFileWriter` writes atomically after backing up a replaced file (`<name>.<time>.bak`, in `ImportReport.Backups`). `JawsSettingsImporter` (`FindSettingsFolder`: the newest `%APPDATA%\Freedom Scientific\JAWS\<version>\Settings\<lang>`) does the same for `default.jcf` (rate, punctuation, typing echo), `default.jkm` and the browsers' `.jkm` (script names to commands) and `.jdf` dictionaries; `docs/switching.md`.
- **Settings**: `SettingsManager` + `SettingsMonitor` expose `IOptionsMonitor<VoxSettings>`; read `CurrentValue` at use time for live reload. The input gestures dialog (`InputGesturesDialog`, opened by `OpenInputGestures`) edits a `GestureEditor` (layout bindings plus the user keymap, per key three slots: browse, focus, outside pages) and saves only the differences as the user keymap; new keys come from `KeyInputDispatcher.CaptureNextKey`, which swallows the next non-modifier key and hands it over instead of running it. Command search (`CommandSearch`, `CommandSearchDialog`) lists commands matching typed words with their keys. The Vox menu (Insert+N, `VoxMenu.Items`; a list in a `VoxMenuDialog`, and the `VoxTrayIcon` right-click menu, not in secure mode) runs the chosen command after its dialog has closed; Pause speech (Insert+S) mutes the speech queue beside sleep mode. The settings dialog (Insert+Ctrl+G, `SettingsCommands`) shows `SettingsPages` (data: `ToggleField`/`NumberField`/`ChoiceField` with a getter and a `with`-setter) as tabs in `SettingsDialog`; each change goes through `SettingsMonitor.UpdateSettings` at once and Cancel restores the opening settings. Vox dialogs other than the Elements List and find prompt use `BrowseModeController.BeginOwnDialog`/`EndOwnDialog` (via `VoxDialogClosedEvent`) to turn browse keys off while open. Saves are atomic (temp file + move); a file that fails to parse on reload leaves the current settings in place. Settings files carry `SchemaVersion` (`VoxSettings.CurrentSchemaVersion`; none means 1): an older file is migrated step by step on its JSON (`SettingsMigrations`) and saved, with the old file kept as `settings.v<N>.json`; a file from a newer Vox is read but never overwritten.
- **Classification helpers**: `FormControls` (form field / needs-Focus-mode, by control type and ARIA role — plain `<ul>`/`<li>` are not form fields) and `ControlTypeNames` (spoken names; structural types like Text/Group are not spoken) are shared by the buffer, `NavigationManager` and `AnnouncementBuilder`. `VerbosityProfile` controls what `AnnouncementBuilder` includes per `VerbosityLevel`. Descriptions (`aria-description`/`aria-describedby` as UIA FullDescription, else HelpText) are captured into `VBufferNode.Description` / `FocusChangedEvent.Description` and said last, except at Advanced verbosity or when they repeat the name or value.
- **Testability seams**: `ISpeechEngine`, `IKeyboardHook`, `IEventSink`, `IAudioCuePlayer`, `IVBufferElement`, `ITextDocument`, `IFocusedTextSource`, `IForegroundWindow`, and injectable clocks (e.g. `LiveRegionMonitor(Func<DateTimeOffset>)`). The end-to-end test-page corpus is `tests/pages/` (`manifest.json`; `TestPageCorpusTests` keeps it in step). Test helpers live in `tests/Vox.Core.Tests/TestSupport/` (`RecordingSpeechEngine`, `CapturingLogger`, `FaultyElement`, `FakeBrailleDisplay`, `FakeBrailleTranslator`). Tests mirror the `src/Vox.Core` folder layout under `tests/Vox.Core.Tests/`.

## Key Conventions

- Target framework: `net9.0-windows10.0.19041.0` (all projects); nullable and implicit usings enabled
- Use `Microsoft.Extensions.Hosting` for DI and app lifecycle; register new components in `ServiceRegistration.cs`
- Use `System.Threading.Channels` for inter-component communication
- Prefer `IUIAutomationCacheRequest` for batching UIA property reads
- All UIA interop goes in `Vox.Core/Accessibility/`
- Speech engine abstracted behind `ISpeechEngine`; input behind `IKeyboardHook`
- Keybindings belong in `assets/config/default-keymap.json` (NVDA conventions, Insert as modifier), not hardcoded; every `NavigationCommand` needs a name, description and category in `CommandCatalog` (the one source for help, the gestures dialog and the guide; a test enforces it)

## Critical Constraints

- **Keyboard hook callback must be < 1ms**: only post to the channel, never process — Windows silently unhooks slow hooks
- COM objects are apartment-threaded; never share UIA objects across threads without marshaling
- Requires Windows 11; Chrome 126+ / Edge for full UIA web content trees. Elevated windows are readable only with UI access (signed install) or when Vox runs elevated
- Pre-initialize the speech engine at startup to avoid first-utterance delay

## Planning Workflow

Development is driven by an autonomous "Ralph loop" (`loop.sh` / `loop.ps1`, prompts in `PROMPT_plan.md` / `PROMPT_build.md`):

- `specs/*.md` — per-subsystem requirements: Phase 1 (input, UIA, virtual buffer, navigation, speech, first-run) and the commercial-parity workstreams (robustness, desktop text, review/object nav, speech & audio, web parity, braille, Office apps, product/settings, OCR & AI, extensibility, quality engineering) and Milestone F, switching from other screen readers (`switching.md`)
- `IMPLEMENTATION_PLAN.md` — task checklist; each task references its spec. Build mode implements the first unchecked `- [ ]` task, validates with `dotnet build && dotnet test`, marks it `- [x]`, and bumps the iteration count / date
- `AGENTS.md` — short operational guide loaded every loop iteration (keep under 60 lines; keep it consistent with this file)
- `COMMERCIAL_PARITY_PLAN.md` — gap analysis against JAWS/NVDA/Narrator and the milestone order (A–E) the parity tasks follow; it reorders `PLAN.md` Phases 2–4
- `PLAN.md` — long-term phased roadmap (Phase 3 adds a C++/CLI `Vox.NativeHelper` for IAccessible2, not yet present)
